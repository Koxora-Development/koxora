# ADR 0014: Portable viewport core and replaceable SVG canvas

- Status: Proposed for Product Owner review with Phase 2.2
- Scope: EDIT-001, EDIT-002; CORE-001 through CORE-007 and CORE-009 through CORE-019 as applicable
- Date: 2026-10-22

## Context and comparison

Phase 2.2 adds genuine navigation to the approved local-first workspace. Element creation, selection, dragging, resizing, routing, undo, and family-specific editing are later milestones. The renderer must not become the portable document model. Existing Phase 2.1 storage, unknown extension preservation, assets, security, and native Save As remain authoritative.

## Decision proposed by this implementation

Use `@koxora/editor-core` for framework-independent geometry, viewport operations, grid/snapping, view-state adaptation, scene bounds and culling. Studio owns browser pointer/wheel/keyboard/ResizeObserver integration and an interchangeable SVG adapter. Web and Tauri use the same Studio implementation; there is no network or platform dependency in the core. SVG primitives remain outside React's reconciliation subtree. A requestAnimationFrame batches transient transforms and culling; project state changes only at gesture boundaries or explicit settings actions.

A camera is a **world-space center** `(x, y)` plus positive zoom, with screen coordinates in **CSS pixels**:

`screen = (world - cameraCenter) * zoom + viewportSize / 2`

The inverse is tested independently. Resize retains the world center, including expanded application view and OS fullscreen resizing. DPR never multiplies pointer coordinates; SVG rasterization is delegated to the browser. Fractional CSS dimensions are measured without integer `clientWidth` rounding. Zoom clamps to 0.02–16 (core callers can supply other valid limits), navigation centers to ±10^12 world units. Pointer-centered zoom uses the _clamped_ zoom when solving the new center. Imported out-of-range cameras are displayed through bounded normalization without rewriting them on open, resize, export, or a grid-only change.

## Portable state and compatibility

No ZIP layout or schema-version bump is necessary. `page.viewport.{x,y,zoom}` was already present; this ADR defines its previously unspecified center semantics. Optional namespace `page.presentation["org.koxora.canvas"]` contains `{version:1, visible:boolean, snap:boolean, spacing:number}`. Spacing is 1–1024 world units, default 24. Unknown sibling and nested fields survive writes. Invalid optional known values use defaults for display and are normalized only when changed. Unknown namespace versions remain untouched and page navigation is session-only for them, with an explicit notice.

`manifest.extensions["org.koxora.workspace"]` stores `{version:1, documentId, pageId}` on an explicit page selection. Invalid/missing references fall back to the first page; a newer workspace namespace is preserved without persisting selection. Theme, language, viewport pixel dimensions, DPR, and expanded-window state are device/session preferences, not project data. Grid visibility is independent of snapping. At low zoom the rendered grid coarsens in powers of two; the snap function still uses the original world spacing.

Gesture commits flow through existing repository autosave, CAS conflict checks and recovery. Explicit save/export and page/dashboard transitions snapshot an in-flight camera synchronously. A load generation remounts the canvas on open/import/recovery and rejects stale callbacks, even when project/page IDs are unchanged. A stored previous snapshot therefore cannot be overwritten by the discarded view. Untouched imported archives still satisfy the existing byte-preserving export regression.

## Honest rendering and future boundaries

Imported content receives a **read-only geometry preview**: rotated bounding rectangles, plain-text labels and connection polylines. Hidden layers/ancestors are respected. No imported HTML, SVG, URLs, style code, font, or binary asset is executed by the renderer. This is explicitly not faithful specialized shape/asset rendering. Originals stay in the domain unchanged.

Culling is linear in scene size; hidden-layer resolution memoizes complete ancestor paths. Paint order is stable across culling. A frame displays at most 1,500 intersecting nodes and 1,500 connections, with a visible dense-view notice. This limit affects preview only. Large scene bounds are still used by Fit. The [performance protocol and results](../development/interactive-canvas.md#performance) document the tradeoff; this is not a claim of unrestricted 10,000-element interactive editing.

Phase 2.3 should extend the scene adapter/render primitives for text, shapes, anchors, connectors, family-specific rendering and creation commands. Phase 2.4 should introduce document commands, hit-testing/selection, dragging with `screenToWorld` and `snapPoint`, resizing, deletion and undo. Phase 2.5 should integrate toolbars, inspectors and context menus around those commands. Those features are not implemented as inert controls here. Revisit spatial indexing, Canvas/WebGL or a third-party renderer when representative editing workloads justify it; the camera and persisted format do not depend on that choice.

## Consequences and acceptance

We own input lifecycle and accessible navigation, but avoid an additional runtime dependency and irreversible library model. Keyboard arrows, zoom/reset/fit buttons, visible focus, localized help, pointer capture, touch pinch and pen pan are implemented. Expanded view makes background UI inert, contains focus and restores it on exit. Reduced-motion navigation is immediate; there is no inertia or animated camera. Physical trackpad, pen, Wayland fractional scaling and screen-reader behavior still need platform acceptance beyond synthetic browser coverage. See the linked development guide for checks, limitations and manual cases.

## Phase 2.3 follow-up

[ADR 0015](0015-shapes-text-connections.md) extends the same SVG adapter with editable basic shapes, text, styles and connections. Its pure geometry, layer ordering, bounded label rendering, endpoint picking and immutable transactions supersede the read-only preview description for supported content. The camera, CSS-pixel coordinate and portable view-state contracts remain unchanged.
