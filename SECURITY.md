# Security reporting

There is no released application or supported product version yet. Never put sensitive security details, real credentials, or confidential files into public issues or pull requests.

## What to send first

Write to `security@koxora.app`, in English or German, and keep that first message free of anything that would help somebody exploit the problem. It is enough to say that you have found a security problem, roughly which part of the project it concerns, and how we can reach you. Please leave out the steps to reproduce, any proof of concept, logs, captured data and screenshots showing real data.

We answer to agree a channel for the details, and the technical part belongs in that channel, not in the first message.

## Why the first message is deliberately thin

The Product Owner has provisioned `security@koxora.app`. Its inbound and outbound delivery and the access to it have not been tested yet, so nobody can promise today that a message reaches a person, or that only the intended people can read it. Until the operator has verified both, the address is a way to make contact rather than a channel for sensitive material, and asking you to send exploit details to it would be asking you to take a risk on our behalf.

This policy promises no response time, no encryption key and no reward. If you receive no acknowledgement, or the matter is urgent, reach the repository owner through a private contact you already have — again without the technical details — so that a channel can be arranged another way. Do not publish the report in the repository.

## Before a public pilot

Confirm that the mailbox receives and sends, confirm who can read it, name the people responsible for it, agree a handling process, and update this policy with what was actually established, including whether a first message may then carry the technical details. GitHub Private Vulnerability Reporting is a possible later option; this document does not claim it is enabled.
